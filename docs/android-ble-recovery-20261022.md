# Android BLE recovery correction — 22 October 2026

Two deterministic software defects are corrected independently of physical clock acceptance:

1. A synchronously rejected host notification was removed from the queue head and appended to its tail. In the actual drain-method harness, `[A1, A2, B1]` submitted `A2` after rejecting `A1`, corrupting framed message order. The candidate uses a deque and returns the rejected packet to the head **before** releasing the pending flag. Accepted packets still wait for the existing notification callback; timestamped clock packets are not newly queued or replayed.
2. Android appended iPhone's `STB1` abort/replacement header to an unfinished frame, swallowing the following control message until timeout. It also delivered idle abort markers as empty JSON. The candidate resets on a complete bounded header and consumes zero-length abort markers silently. Checking all eight header bytes and the length prevents a printable base64 continuation beginning `STB1` from falsely resetting an intact frame. This is the existing JSON/base64 protocol, not support for arbitrary binary framing or new STK1 capabilities.
